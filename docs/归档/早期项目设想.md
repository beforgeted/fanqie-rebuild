当前实现版本：1.13.1；无限滚动、候选／不想看标记、统一筛选界面、关键词标签、单本／批量加入官方“待看”、书库简介阅读框、候选集中复筛与备注、选书方案与关键词分组已实现。阶段顺序为建议，尚未承诺排期。

## 一、目标与理想体验

产品方向暂称“番茄选书台”：利用电脑的大屏幕、浏览器扩展、本地偏好和 AI，帮助用户更精准地筛书、比较候选，并记住每次判断。

核心目标：减少翻页、重复浏览和反复打开详情的时间，让用户更快找到值得开始读的书。以实际选书效率为目标，不以刷到更多卡片或停留更久为目标。

首要使用场景：浏览“动漫衍生”分类，排除原神、崩铁、崩坏3、绝区零、鸣潮等不想看的二游题材，同时发现符合当前兴趣的作品。

理想流程：

> 选择偏好方案 → 连续浏览 → 查看匹配依据与完整简介 → 留下候选 → 逐本复筛与试读 → 记录反馈 → 下次接着找。

不开启 AI 时，也应能完成完整选书流程；AI 用于进一步整理信息和辅助判断。

## 三、产品想法清单

### 1. 分层偏好与选书方案

- [ ] 硬性排除：明确不接受的题材或条件，匹配后隐藏。
- [ ] 偏好排序：喜欢的世界观、篇幅、状态等影响顺序，不必全部作为硬限制。
- [ ] 当前心情：临时条件只影响本次选书，可随时取消。
- [x] 保存多套选书方案；首版独立保存关键词组、启用屏蔽及匹配简介开关，原站分类／排序不自动切换。
- [x] 关键词分组与别名管理，例如星穹铁道、崩铁、星铁；用户自行命名和归组，不自动推断别名。
- [x] 每组实际匹配词可见可编辑，支持整组启停与勾选移组；不自动追加角色名或其他规则。

说明：示例用于表达产品能力，不代表用户已经确认全部偏好。现有关键词隐藏仍作为可独立使用的确定性规则保留。

### 2. 可解释、可纠正的筛选

2026-11-21 决定暂缓误屏纠正，不将其作为当前下一步；保留已有关键词记录与临时显示。优先改善直接浏览简介和人工筛书的效率。

- [ ] 展示符合条件、冲突条件与待确认信息。
- [ ] 展示命中的字段、关键词和原文片段，让用户知道为什么隐藏或降低优先级。
- [ ] 支持撤销误屏蔽，并考虑单书例外；重新遇到该书时尊重用户修正。
- [ ] 区分字面命中、题材明确匹配与信息不足；简介提及某词不必然等于该书属于该题材。
- [ ] 将现有记录清单扩展成可检查、可纠正的筛选记录页。

不凭简介生成伪精确的“作品质量分”。如引入匹配度，必须说明它反映偏好匹配，不代表文笔或作品质量。

### 3. 面向电脑的连续浏览界面

- [x] 接近底部自动加载下一页，并让新书继续参与屏蔽、记录和整齐补位。
- [ ] 左侧条件区：分类、篇幅、状态、包含／排除条件、已保存方案。
- [ ] 中间书流：封面卡片与紧凑列表两种显示方式。
- [ ] 右侧详情区：完整简介、实际可取得的书籍信息、匹配理由、疑点和个人笔记。
- 保留书籍详情在新标签页打开的现有行为，原书库标签页继续保留当前列表。
- 已取消浏览位置恢复：刷新书库重新获取当前列表，不重建之前累计加载的页面或滚动位置。偏好方案的保存仍单独规划。
- [ ] 常用操作支持键盘，减少鼠标来回移动。
- [ ] 显示已加载、可见、屏蔽数量，避免把本地结果误当作全站统计。

三栏是宽屏下的目标草案，具体布局与窄窗口行为仍需设计。

### 4. 候选清单与逐本复筛

- [x] 将感兴趣的书暂存为候选，不必立即决定阅读。
- 已取消：候选并排比较。用户逐本判断是否感兴趣，不要求对候选排序或分出优劣。
- [x] 保留“为什么留下它”的个人笔记（1.9.0 可选备注，仅本地保存）。
- 后续仅在有实际需求时补充单本资料，不默认增加对比视图。
- [ ] 后续 AI 辅助整理单本资料时给出依据，具体范围另行确认。

不存在或无法取得的字段应显示未知，不能补造。

### 5. 自然语言与 AI 辅助筛书

- [ ] 用户用自然语言表达需求，AI 将其转换成可见、可编辑的筛选条件。
- [ ] 明确区分硬条件和偏好；歧义条件允许修正，不静默加入永久排除。
- [ ] 从可取得的简介、标签等信息中提取世界观、设定与题材元素。
- [ ] 支持追问：为什么推荐、为什么没有过滤、哪些卖点相似、哪些可能不符合条件。
- [ ] 以喜欢作品的指定元素寻找相似候选，允许保留设定而更换世界观。
- [ ] 对候选进行带证据的归纳与比较，信息不足时明确回答不知道。
- [ ] 若后续能取得合法可访问的试读内容，再探索试读辅助分析，注明实际分析范围。

AI 服务商、模型、调用方式和预算尚未确定。远程 AI 所需上传字段、缓存与删除方式需在实现前明确；当前版本仍然只在本地处理数据。

### 6. 个人选书状态与反馈

- [ ] 浏览过简介：淡化或隐藏，减少反复查看。
- [x] 候选：沿用原本地“待看”数据，留待集中筛选；官方“待看”表示准备阅读。
- [ ] 已试读：记录阅读位置与第一印象。
- [ ] 弃书／不想看：记录原因，并支持撤销。
- [ ] 暂缓：有兴趣但想等字数、完结或其他条件满足。
- [ ] 将反馈推广为长期偏好前，让用户选择“只针对这本书”或“今后也参考”。

状态设计原则：看过简介不等于喜欢，暂缓不等于排除；现有“我已处理”不能自动迁移为“已读”或“已向官方屏蔽”。

### 7. 精准筛选与探索发现

- [ ] 严格筛选：遵守明确条件，优先精准。
- [ ] 日常发现：保留硬性排除，适当放宽软偏好。
- [ ] 换换口味：尝试不同设定，同时继续遵守硬性排除。
- [ ] 按书籍的个人状态减少重复筛选；不以记住滚动位置来替代个人状态。
- [ ] 查看暂缓作品是否已达到字数或完结条件。

探索模式不得悄悄重新推荐用户明确排除的题材。自动定期检查或通知属于后续可选能力，不默认开启。

### 8. 可积累、可备份的个人资料

- [ ] 维护个人标签、别名、偏好方案与例外名单。
- [ ] 保存待看、试读、弃书记录及一句话评价。
- [x] 扩展版导出和恢复结构化配置包，提供格式版本、跨浏览器兼容、合并去重和冲突确认。
- [ ] 提供清晰的数据管理与删除入口。
- [ ] 后续评估跨设备同步；本阶段优先做好本地数据可靠性。

这是扩展自己的选书体系，不宣称与番茄账号的官方屏蔽或阅读记录同步。

## 四、建议实施阶段与验收标准

### 第一阶段：顺畅逛书

范围调整：无限滚动已完成；“候选／不想看”手动标记已实现并验证跨标签页同步。浏览位置恢复已取消；详情侧栏和“看过”状态暂留后续讨论。

验收要点：

- [ ] 连续追加多页时无重复书籍，新书立即执行现有屏蔽与记录规则。
- [ ] 过滤后保持布局对齐；某页全部被过滤时能合理继续加载，并可暂停，避免无止境请求。
- [ ] 加载中、失败重试、没有更多内容的状态明确。
- [ ] 更换分类、排序或筛选条件后，旧请求结果不会混入新列表。
- 刷新书库使用最新请求结果，不恢复旧书流；关键词、屏蔽记录及未来个人标记独立持久保存。
- [ ] 浏览状态能够保存、撤销，并与原有屏蔽记录并存。
- [ ] 长列表不会因无限堆积元素造成明显卡顿，必要时采用分段保留或虚拟化。

键盘操作和双视图可按试用反馈分批补齐。跨会话浏览位置恢复不在项目范围内。

### 第二阶段：精准筛书

建议范围：偏好方案、别名词组、筛选依据、单书例外、候选清单与逐本复筛。

验收要点：

- [ ] 硬排除与软偏好行为清楚，切换方案不意外修改其他方案。
- [ ] 每次隐藏能查到依据，用户可纠正误判。
- [ ] 比较信息可追溯到原始字段，缺失项明确标注。
- [ ] 手动排除和已有状态在再次遇到同书时仍然有效。
- [ ] 偏好、书单和反馈能导出并恢复。

### 第三阶段：AI 辅助

建议范围：自然语言条件转换、书籍元素提取、带依据的匹配解释与候选比较。

验收要点：

- [ ] AI 生成的条件可见、可编辑，不擅自修改永久偏好。
- [ ] AI 对书籍的事实判断附有来源字段或原文依据，无法确认时显示未知。
- [ ] 不将简介分析冒充全文阅读，不将匹配度冒充质量评价。
- [ ] AI 不可用、超时或达到预算时，基础浏览和筛选仍可使用。
- [ ] 用户知道哪些数据会交给远程服务，调用范围和费用控制可理解。

探索模式、暂缓作品复查和跨设备同步在核心流程试用后另行排优先级。

## 五、实现前需要验证的事项

- 当前番茄书库分页方式、终止条件、分类／排序切换行为，以及列表是否返回完整信息。
- 字体变化对新加载数据的影响；现有字体映射不代表永久兼容。
- 评分、阅读人数、更新时间等字段的实际可得性，不预先承诺所有卡片都能显示。
- 接管现有页面还是提供独立选书界面：先评估在现有扩展上渐进增强的方案。
- 长列表去重、取消过期请求、限流与性能策略。
- 本地记录的数据结构升级，确保现有屏蔽记录和用户设置不丢失。
- 引入第三方代码前核对许可证、维护状态及与现有插件的兼容性。

## 七、如何判断这次重构有用

试用时重点观察：

- 从开始找书到留下愿意试读的候选，是否更省时间。
- 是否减少重复查看同一本书、反复翻页和打开详情标签页。
- 误屏蔽是否容易发现并纠正，不想看的内容是否仍频繁出现。
- 推荐和筛选理由是否帮助决策，AI 是否提供了实际增益。
- 长列表、数据保存、恢复和撤销是否稳定。

先用实际选书任务建立体验基线，再决定具体指标，不预设无法验证的提升百分比。
