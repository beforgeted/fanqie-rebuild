## 每组执行的完整流程

1. 书库首批 18 本按规则隐藏，再追加 18 本；36 个唯一书籍 ID，无重复。
2. 点击实际可见书流的文字区域，等完整简介加载后加入候选，进入选书并保存备注。
3. 打开候选只读核对模拟官方书架，不自动写入。主动同步时先模拟加书成功、移分组 HTTP 503；重试后同书只加一次，分组移动成功并回读确认。旧失败候选也由统一重试处理。
4. 修改未保存备注草稿，往返数据管理后，当前书、草稿和列表位置保留。
5. 在 1366×768、1280×720、1024×768 检查简介、同步和下一本操作区域的非零尺寸及视口边界。
6. 返回书库核对原 URL、滚动位置和累计列表节点身份相同；另一个详情页标记“不想看”，原书流随之隐藏对应书籍。
7. 预览清理、真实下载 JSON 文件、手动确认已保存，然后清理一条旧自动记录。候选及有备注书籍的关联记录保留；个人备注和规则不变。通过文件选择器导入备份恢复被清理的记录。

既有 npm test 回归通过：13 个模块测试，以及手动标记、方案、屏蔽历史、无限滚动、官方客户端／UI、简介、候选／备注／按键、备份／清理 UI、导航及缓存失效集成测试。npm run check 构建一致性、版本与语法检查通过。

## 发现与处理

- 覆盖文件后仅重启不能替代扩展管理页“重新加载”；原位更新说明明确保持开发者模式、等待加载完成并刷新网页。验证同时检查实际后台代码，避免只看 manifest 版本。
- 发布脚本以明确文件列表打包，生成 SHA256；不会把本地依赖、个人记录或调试资料打进去。
- 测试脚本修正模拟页面字体／排序参数、可见书流定位、简介加载完成条件及跨标签页激活；这些属于验收设施修正，没有为通过测试修改产品筛选规则或删掉旧数据。
- 测试发现重新加载会销毁调试工作线程，因此等待原生管理页完成后重启，再重新取得后台连接。没有依赖已失效连接判断产品状态。

## 边界与复现

所有业务页面、封面、详情及官方接口使用模拟响应，浏览器使用专用临时资料目录；未读取个人浏览器记录，未写真实官方书架，未清理真实数据。本报告验证本地实现与已知模拟协议，不保证未来官网改版或线上接口行为；未重新宣称性能提升、手机测试或所有历史版本均已覆盖。

先运行 npm run package，再运行 npm run test:release。需要 Windows、Chrome／Edge、完整 Git 历史及本地 devtools-runtime 的 Chrome DevTools MCP／Puppeteer 运行库。报告中的两个版本是固定基线；重跑结果写入 .local/release-qa.json，截图保存在控制台输出的独立临时目录。
