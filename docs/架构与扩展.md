# 架构与扩展

当前版本：1.13.0。目标是让修改位置清晰、业务逻辑可单独测试，后续接入分析服务时不用修改存储或官方书架协议。页面交互、存储键和安装目录保持兼容。

## 目录与职责

```text
src/

  adapters/fanqie/             官方书架协议、详情解析、字体映射与文字读取
  platform/chrome/            扩展存储桥接、后台串行写入
  platform/userscript/        脚本声明、油猴存储桥接
  services/                   分析服务契约、校验、取消与超时
  features/
    library/                  筛书、对齐、无限加载
    rules/                    规则面板、方案、关键词编辑与布局
    history/                  屏蔽记录面板
    choices/                  候选／不想看标记、列表、页面绑定
    review/                   集中复筛与备注
    intro/                    卡片简介阅读框
    shelf/                    官方待看同步的交互与调度
    shell/                    原站入口与展开窗
    backup/                   导出／拖入恢复界面
  app/                        常量、共享状态、服务装配、启动及片段顺序
scripts/                      构建与一致性检查
tests/unit/                   独立核心、架构与分析接口测试
tests/integration/            模拟页面和存储的功能回归
tests/browser/                独立 Chrome／Edge 的迁移验证
docs/legal/                   第三方来源与开发依赖许可
chrome-extension/             可安装的构建产物，保留原路径
fanqie-keyword-filter.user.js  可安装的构建产物，保留原下载地址
```

运行时不引入 npm 依赖，jsdom 只用于测试。不要直接编辑根目录用户脚本和 chrome-extension 内的生成文件。

## 模块边界与当前限制

core、分析服务、官方书架客户端、文字读取器是可直接 import 的独立模块。core 通过传入的 storage 操作数据；书架客户端通过传入的请求函数访问官方协议，不依赖界面。analysis-service 通过传入的资料读取器和 provider 工作，不持有存储或书架客户端。

页面部分采用渐进拆分：features 中的文件以及 book-details.fragment.js 目前仍按 src/app/runtime.json 顺序拼接到同一个闭包，保留原有状态和事件生命周期。它们是按职责划分的源码片段，**还不是能任意单独加载的界面组件**。涉及共享变量的修改需检查调用方，不应随意调整清单顺序。后续修改某个复杂功能时，再将其提取为显式依赖的控制器，避免一次重写全部交互。

`src/app/services.js` 是统一装配点，目前提供 `bookDetails.load(id, force)` 和默认禁用的 `analysis`。卡片简介和候选复筛已通过 bookDetails 服务取得资料，仍使用原有缓存和失败处理。启动位于 bootstrap.js，服务装配必须先于启动。书架写入继续使用原有明确的用户操作、账号核验和后台串行流程。

## 新增或修改功能

1. 纯数据处理优先放 core，以参数传入数据和存储，不读取 document、chrome 或页面全局变量。
2. 官网接口或 DOM 结构变化放 adapters/fanqie；浏览器差异放 platform，避免每个功能各写一套。
3. 界面代码放对应 features 子目录；新增片段需加入 runtime.json。新业务依赖在 app/services.js 装配，避免模块导入时启动请求。
4. 新增独立模块时在 scripts/build.cjs 列出，并补充直接导入测试。当前构建只支持本地具名导入、函数或列表形式具名导出，不支持重命名导入、循环依赖、动态导入或第三方包；需要这些能力时应更换为标准打包器。
5. 修改后运行 `npm test` 和 `npm run check`。涉及扩展权限、存储桥接或导入导出时，加跑 `npm run test:browsers`。

构建会生成带 `SOURCE` 标记的两个平台产物，便于在开发者工具中定位源码。check 同时检查产物一致性、模块真实导入、脚本语法和版本号；默认回归会检查所有页面片段是否都纳入构建。扩展和用户脚本共享同一份核心实现。

## 后续 AI 接入接口

接口位于 `src/services/analysis-service.mjs`，提供方类型见 `analysis-contracts.d.ts`。当前没有模型、API Key 配置、AI 按钮或自动请求；`available` 为 false，调用会返回 `NOT_CONFIGURED`，连资料加载也不会触发。

未来可在装配点注入以下提供方：

```js
const analysis = createBookAnalysisService({
  loadBook: fetchBookDetails,
  provider: {
    id: 'chosen-provider',
    async analyze(book, {signal}) {
      // 在未来明确授权的分析操作中调用模型；不得在构造时请求。
      // 这里只演示契约，不包含联网实现。
      return {summary: '', findings: [], unknowns: ['尚无分析结果']};
    }
  }
});
const result = await analysis.analyze(bookId, {signal, timeoutMs: 30000});
```

- 输入仅含书籍 ID、书名、作者、简介、元信息及官方详情来源。原记录上的备注、候选状态、账号字段、Cookie 不会传入。
- 输出为摘要、带原文引用的发现和待确认问题。每条发现限定 title／abstract／meta 字段，引用必须真实出现在对应资料中；不接受伪造引用。校验引用存在不等于证明模型判断正确，未来界面仍需显示依据并允许人工判断。
- 输出只返回给调用者，不保存、屏蔽、加入候选或同步书架；这些操作继续由用户决定。
- 支持 AbortSignal 和超时。取消加载后的迟到结果不再调用提供方；提供方也应响应 signal，及时停止自身请求。现有详情加载器有独立超时及缓存，取消分析不强制中断共享详情请求。
- 稳定错误码：NOT_CONFIGURED、INVALID_BOOK、INVALID_RESULT、ABORTED、TIMEOUT。资料读取及提供方原有异常继续向上传递，由未来界面处理。

模型选型、密钥管理、费用控制、提示词、批量分析调度、结果持久化与 AI 界面仍属于后续阶段，尚未实现。

## 独立页面与抽屉

features/shell/selection-page.js 负责同源独立选书页、原生内容避让、页面状态与右侧抽屉布局；drawer.js 保留公共面板及其事件。src/app/state.js 定义路由识别，独立地址复用官网有效的 library 路由，不需要服务端重写。仅在 fq_view=selection 时隐藏原生书库内容，保留官网头部；离开该路由时恢复宿主。独立页绕过无限书库加载与关键词记录，不增加后台请求流。官方书架 API 和扩展存储桥接保持同源及原有权限。

个人页面与筛书抽屉复用已有界面节点和存储操作，入口按路由分流，不复制候选数据或写入接口。新入口测试位于 tests/integration/verify-selection-page.cjs；原有候选、官方同步与备份回归切换到独立页面地址执行。
