# 番茄书库重构 · 项目计划

更新时间：2026-11-21

当前实现版本：**1.13.6**。本文前八节是当前计划；后续章节保留需求决策和实施历史，发生冲突时以本节及较新决策为准。

## 一、产品目标与核心流程

把选书功能融入番茄原网页。扩展只是交付载体，新增操作优先放在相关页面内，保持首页、书库、书架与我的选书的导航一致。

核心流程：**选择方案 → 连续逛书库 → 看简介 → 留下候选 → 逐本复筛 → 加入官方待看 → 手机阅读**。

不开启 AI 也能完整使用。以减少重复操作、稳定保存个人判断为目标，不把早期想法全部视作必做功能。

## 六、已取消、暂缓及边界

- **已取消：候选并排比较。** 不要求用户为小说排优劣，不作为后续缺口。
- **已取消：跨刷新恢复旧书流。** 刷新从地址栏对应页重新获取；同一标签页切换时保留现场是另一项已实现能力。
- **暂缓：误屏纠正与单书例外。** 继续保留既有屏蔽记录、临时显示及手动标记撤销。
- 浏览简介不等于已读；本地候选不等于官方待看；本地“我已处理”不等于已向官方提交不感兴趣。
- 无限滚动仍保留全部已加载卡片，资源占用随规模增长。本轮千本结果不是任意规模、任意设备的性能承诺；将来确有瓶颈再评估分段保留或虚拟化。
- 第三方字体映射的上游 README 与许可表述仍有待上游澄清，继续单列跟踪，详见 [第三方来源与许可](legal/第三方来源与许可.md)。

## 九、需求决策：取消浏览位置恢复

已确认决定：取消书库浏览位置恢复，不作为延后待办保留。

原因：书籍详情已在新标签页打开，切回原书库即可继续浏览。刷新书库意味着重新获取当前列表，不必重建旧排序、累计书流或滚动位置。

继续保留的数据：关键词设置、屏蔽记录，以及未来手动设置的候选／不想看状态。它们表达用户选择，不属于页面位置缓存。

## 十、待看与不想看：已实现方案

状态：1.5.1 已实现；遵循“功能融入原网页”的界面原则。

### 用户流程

> 书库发现一本书 → 新标签页查看书籍详情 → 阅读简介及原站实际提供的信息 → 标记待看或不想看 → 切回书库继续筛选。

详情页是主要决策入口，书库卡片是快捷入口。“打开详情”本身不代表喜欢、待看或不想看，不自动作出选择。

已检查的当前详情页有简介、目录和阅读／书架按钮，未发现书评列表。首版不承诺评论展示；评论获取、适配和增强需另行调研。

### 建议的首版交互

- 详情页：在“开始阅读／加入书架”附近直接加入“候选／不想看／清除标记”，使用原站按钮样式，原位反馈当前状态，不自动关闭标签页。
- 书库卡片：展示状态，并提供同样的快捷操作；保留点击书名或封面打开新标签页的行为。
- 候选：保存到本地清单，书库仍可见并带标记；沿用原本地“待看”数据，标记本身不自动加入官方书架。
- 不想看：按书籍 ID 在支持的书库／排行榜中隐藏，继续对齐补位；当前详情页保持可访问，提示已保存并提供撤销。
- 同一本书只处于“未标记／候选／不想看”之一。支持相互切换与清除标记，清除后回到未标记。
- 修改成功后明确反馈；失败时显示错误，不假装保存成功。误点可直接撤销，不每次弹确认框。
- 详情页与书库共享状态，其他打开的标签页自动同步；返回前台时再次核对，避免长时间挂起后漏更新。
- 在原网站导航增加“我的选书”，从页面内容区域展开清单，含候选、不想看两个分类；支持按书名／作者搜索、打开详情、改状态和清除标记。
- 当前“屏蔽记录 / 待处理清单”继续保留，新增“待看”不能与它的“待处理”混为一谈。

### 与现有过滤的关系

- 不想看是明确的单书排除，即使没命中关键词，也默认隐藏。
- 待看不自动改动关键词规则。若后来命中关键词，书库仍按规则过滤，但待看清单保留该书并提示冲突，可从清单打开详情。
- 清除不想看只撤销手动排除；若仍命中关键词，仍会被关键词规则隐藏，并显示对应原因。
- 统计按书籍 ID 去重，同时命中两种规则的书只计一次隐藏，可分别展示命中原因。
- “临时显示已屏蔽”可用于检查关键词和手动隐藏的书，显示行为不修改个人状态；具体文案在实现时区分来源。
- “我已处理”是原有本地处理进度，不迁移为候选、不想看或官方操作成功。

### 数据与实现方向

- 用书籍 ID 作为身份，保存状态、书名、作者、详情链接和修改时间；不缓存旧书流或滚动位置。
- 使用独立的个人标记存储，保留已有关键词设置和屏蔽记录。
- 多标签页写入串行处理；跨标签页通知后局部更新状态与显示，避免整页刷新、重复请求书库或清空已加载书流。
- 仅更新标记不自动触发连续加载；避免书籍被隐藏后因为底部进入视口而连续抓取多页。
- 首版优先 Chrome；保留油猴版本的兼容路径，跨标签页通知方式在实现前验证。
- 标记本身是本地个人选择；只有用户点击“加入官方待看”才调用官方书架，不调用 App“不感兴趣”；搜索页、阅读正文页暂不扩展。

### 首版验收

- [ ] 从书库打开详情，标记待看后，原书库显示对应标记，待看清单出现该书。
- [ ] 在详情页标记不想看，原书库隐藏该书并对齐补位，原有已加载书籍保留。
- [ ] 关闭详情、刷新书库、重启浏览器后，手动状态仍在；后续加载再次遇到同书时立即应用。
- [ ] 打开详情但未点击标记，不产生待看或不想看状态。
- [ ] 撤销、清除和两种状态互转有效，其他标签页同步；写入失败可见且可重试。
- [ ] 同时命中关键词和手动排除时不重复计数，清除手动排除不会意外绕过关键词。
- [ ] 在个人清单打开被排除的书仍可查看详情和撤销，数据入口不会因隐藏而消失。
- [ ] 原有无限滚动、自动记录、临时显示、记录导出和对齐补位不回退。

原首版暂不纳入：AI、评论接入、自动推断偏好、原因必填、阅读进度。官方书架同步已在 1.7.0 扩展实现，范围见下文；本地偏好和记录跨设备同步仍未实现。可在实际使用后再决定是否需要。

## 十一、界面原则：功能融入原网页

已确认：本项目重构的是用户看到的番茄网页体验。扩展仅作为加载改动的技术载体。新增功能优先放入原页面中语义相关的位置，沿用网站的视觉、布局和操作习惯，不默认新增独立悬浮面板。

- 详情决策按钮放在开始阅读、加入书架附近。
- 书库快捷操作放在书籍卡片内部，状态同步后原地更新与补位。
- 个人选书清单通过网页导航进入独立选书页，在当前标签页切换，切回书库恢复本次浏览的分类、排序、已加载书流及位置；沿用原站导航和视觉。
- 按 1.9.1 界面调整，关键词、屏蔽记录和浏览设置融入原站右侧工具栏的“筛书设置”，按需展开，不再占用书库顶部空间。
- 已验证详情页标记后原书库自动隐藏、清除标记后恢复，原已加载书流不清空。


## 十二、统一选书与筛选（1.6.0）

- [x] 候选、不想看、关键词规则、屏蔽记录在同一展开窗中切换，内容独立滚动。
- [x] 支持关闭按钮、Esc、背景关闭和键盘焦点约束，防止滚动穿透到书库。
- [x] 筛选栏放在原生分类和排序之后、书籍列表之前，提供规则摘要、简介匹配、临时显示、记录和浏览设置入口。
- [x] 复用原有存储键与记录处理逻辑，不迁移或清空关键词、个人标记和处理进度。
- [x] 保留无限滚动、自动记录、详情页同步、搜索、复制、导出及对齐补位。

展开窗打开时暂停自动发起后续书页请求，关闭后继续沿用现有书流。它不保存跨刷新浏览位置，也不调用官方“不感兴趣”。


### 屏蔽词标签与批量录入（1.6.1）

- [x] 筛选栏展示已生效的词标签，规则页提供逐词删除。
- [x] 换行、中英文逗号和分号、顿号、制表符作为输入分隔符，保留词内空格。
- [x] 新词按现有匹配标准去重，忽略空项和纯标点；已有词表不自动拆分或迁移。
- [x] 支持识别数量预览、批量加入和直接保存；失败保留草稿，关闭丢弃未保存修改。

这里的分隔符用于录入多个关键词，匹配仍沿用原有普通关键词规则，不引入正则表达式语法。


## 十三、候选与官方待看同步（1.7.0）

2026-11-21 已用《废土黑作坊：从造一级弹开始》验证新建官方“待看”并放入书籍，官方接口回读、网页显示及用户手机 App 均确认成功。

当前流程：书库筛选 → 本地候选 → 人工挑选 → 官方待看 → 手机阅读。理想流程在人工挑选环节加入 AI 辅助分析；AI 仍属于后续阶段，本轮不接入模型。

- [x] 本地“待看”统一更名为“候选”，保留原有 later 状态与存储键，不迁移、不清空历史数据。
- [x] 候选清单支持单本同步、勾选批量同步、全选当前搜索结果、失败重试和刷新官方状态。
- [x] 已在其他官方分组的书先列出移动提示，确认后执行；执行时分组已变化则停止该书，要求重新核对。
- [x] 缺少“待看”分组时随第一本创建；已有分组使用精确 ID；长数字 ID 按字符串处理，避免 JavaScript 精度丢失。
- [x] 写入前读取官方状态，成功后回读核验；超时或响应丢失时不自动重复提交，用户重试时先核验。
- [x] 逐本保存排队、同步中、成功及失败状态；批量部分失败保留成功项，支持只重试失败项。
- [x] 同步状态按账号隔离；同源标签页用 Web Locks 排队，防止并发创建同名分组和重复入架。
- [x] 未登录或账号切换明确报错；只使用当前网页登录态，不存储 Cookie 或转发给第三方。
- [x] 保留候选、屏蔽词、屏蔽历史、无限滚动、自动记录、对齐补位及详情页同步。

清除本地候选、标记“不想看”不会删除官方书架数据。官方“待看”可同步手机，本地候选、偏好和屏蔽记录仍仅保存在当前浏览器。

后续保持原理想态顺序：完善精准筛书与逐本复筛，再加入带依据的 AI 分析；服务商、模型、材料范围和预算在 AI 阶段确定。
